# 검증 기록

## 환경과 자동 검증

macOS, Node.js 26.8.1, npm 11.19.0에서 `npm run check`로 TypeScript strict 검사, 45개 Vitest 테스트(jsdom 및 게시 도구 테스트), esbuild 빌드를 확인했다. CI는 Node.js 22/Linux용으로 구성했으나 원격 실행 결과는 별도 확인해야 한다.

테스트는 버튼 삽입·활성화, 조상 숨김·CSS·화면 밖 상태, 중복 클릭 및 재생성, 재시청, browse→watch 진입, 회차 교체, 추천작·상시 다음 버튼 제외, 전체/종류별 OFF 및 복구를 포함한다. 관계없는 자막 변경에서 레이아웃을 재확인하지 않는 동작과 설정창의 저장 실패·초기 읽기 경합도 검증한다.

게시 도구의 6개 테스트는 가짜 Git/CLI만 실행하며 실제 원격이나 인증을 사용하지 않는다. 잘못된 저장소·변경 중인 파일·다른 인증 계정을 거부하는지, 계획 모드가 게시하지 않는지, 정확한 브랜치와 Draft PR만 게시하는지, 기존 PR 재실행 시 중복이 없는지를 검증한다.

## 실제 Chrome의 모의 DOM

`npm run dev`로 연 테스트 UI에서 **13/13** 시나리오 통과:

1. 활성 오프닝 버튼 삽입
2. 비활성 버튼 제외
3. 줄거리 버튼 활성화
4. 조상 숨김 제외
5. 숨김 해제
6. 같은 버튼 및 즉시 재생성 연타 방지
7. 추천작·상시 다음 버튼 제외
8. 전용 다음 회차 클릭
9. 회차 전환 뒤 감지 복구
10. 전체 OFF
11. 전체 ON 복구
12. 투명 요소 제외
13. 실제 CSS 전환 완료 후 감지

이 실행에서 삽입/활성화→클릭 측정 세 건은 **1.70ms, 1.10ms, 1.10ms**였다. DOM 변경 직전과 클릭 이벤트의 `performance.now()` 차이를 기록했다. 표본 세 건의 로컬 확인이며 평균 성능, 상한, Netflix 실서비스 지연 또는 다른 플랫폼 성능을 주장하지 않는다.

모의 브라우저 확인 이후 추가한 OFF 기간의 버튼 재사용 처리는 별도 자동 회귀 테스트로 확인했다.

설정창의 전체 OFF, 개별 줄거리 OFF, 새로고침 후 설정 유지와 하단 표시도 Chrome에서 확인했다. 미리보기는 localStorage 기반 모의 저장소이며 실제 Chrome 확장 저장소 검증을 대신하지 않는다.

## 패키지

`npm run package`로 확장 파일과 한국어 시작 안내만 담은 ZIP을 생성하고 `unzip -t`로 무결성을 확인한다. 실제 생성 ZIP의 SHA-256은 `artifacts/SHA256SUMS`에 기록한다. 소스·개발 의존성·모의 화면·인증 정보는 설치 ZIP에 포함하지 않는다.

## 아직 확인하지 못한 것

- Chrome 확장 설치 상태의 `chrome.storage.local` 및 탭 간 설정 반영
- 실제 Netflix의 버튼 구조·자동 클릭 수용·마지막 회차 추천작·전체 화면
- 계정별/다국어 UI 및 Windows/Linux 실제 브라우저
- 원격 GitHub CI 성공과 PR 게시 (인증 필요)

작업 당시 Netflix 탭은 로그인 화면이었다. 사용자 계정·시청 기록을 가져오지 않았고 실서비스 검증 완료로 간주하지 않았다.

## 수동 통합 확인

ZIP의 extension 폴더를 Chrome에 로드하고 Netflix 탭을 새로고침한다. 오프닝·줄거리·엔딩이 있는 일반 회차에서 각각 한 번만 클릭되는지, 다음 회차에서도 감지가 이어지는지 확인한다. 마지막 회차 뒤 추천작이 자동으로 재생되지 않는지도 확인한다. 전체/종류별 OFF와 다시 ON, 전체 화면, 탭 새로고침을 검증한다. 문제가 생기면 계정 정보나 영상 대신 버튼의 data-uia·표시·비활성 상태만 기록한다.
